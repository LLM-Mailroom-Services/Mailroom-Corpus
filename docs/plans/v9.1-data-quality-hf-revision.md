> **Status:** researched plan (not yet executed)

## 1. Overview

Ship a **quality-first Hub revision** (proposed tag/lineage: **v9.1** / dataset `v1.1`) that closes dated exceptions, hardens LLM-ingestion formatting, aligns token/context contracts with the live Modal+vLLM deployment, and fills the evaluation axes that currently score at floor on correspondence extraction and subclass heads — **without** destroying v9 identity (zero drift on the 3,302 `document_id`s unless a row is explicitly superseded).

This is **not** a large expansion epic. It is a surgical quality pass that can be fully implemented with existing builders (`v9_build.py`, `dataset_export.py`, `intent_backfill.py`, `fixtures.py`, `bundles.py`, `hf_interface.py`) and published via the centralized upload path.

## 3. Modal deployment insights (binding constraints on the revision)

Evidence: hub epic [#193](https://github.com/LLM-Mailroom-Services/mailroom-issues/issues/193), [#194](https://github.com/LLM-Mailroom-Services/mailroom-issues/issues/194), [#195](https://github.com/LLM-Mailroom-Services/mailroom-issues/issues/195); sandbox [#21](https://github.com/Exios66/local-mailroom-sandbox/issues/21), [#32](https://github.com/Exios66/local-mailroom-sandbox/issues/32), [#37](https://github.com/Exios66/local-mailroom-sandbox/issues/37); mailroom-ml [#112](https://github.com/LLM-Mailroom-Services/mailroom-issues/issues/112)–[#115](https://github.com/LLM-Mailroom-Services/mailroom-issues/issues/115), [#121](https://github.com/LLM-Mailroom-Services/mailroom-issues/issues/121), [#126](https://github.com/LLM-Mailroom-Services/mailroom-issues/issues/126).

### 3.1 Serving reality

- Live path: **Modal + vLLM** on **1× L4**, currently `Qwen/Qwen3-8B` / AWQ; measured correspondence run (`run-20-correspondence-awq-c8`, fingerprint `285f423d3708`): 20/20 docs, **0 serving errors**, throughput ~472 tok/s, billed ~$0.056 — but **`overall_extraction_score ≈ 0.087`** (owner gates: diagnostic ≥0.25, pipeline-viable ≥0.50).
- Binding constraint is **KV cache**, not parameter count (#193): at 16k context, ~2 concurrent sequences on Qwen3-8B bf16. Migration target (Qwen3.5-9B+FP8 or Granite 4.2-8B @ 131k — #195) changes context headroom; corpus must advertise **true token estimates + recommended windowing**.
- Cold boot dominates small Modal runs (~64% of billed GPU-sec on the 20-doc draw). Dataset packaging for bulk backfill should favor **warm-pool-friendly batching metadata** (stable sort keys, size buckets already used by DMR-068: 2k/6k/12k char).

### 3.2 Quality vs format (LLM ingestion)

From #21 diagnosis + #32 SAND-026 (merged):

- Floor is **extraction quality / schema adherence**, not serving health.
- Empty GT fields on non–insurance-claim docs must **not** score as misses — owner clarification. The Hub corpus must make **eligibility / documented-absence** machine-readable for scorers (today that knowledge lives in audit JSON / builder comments, not in row-level fields consumers load).
- Parse/schema metrics (`parse_error`, `schema_valid`, `schema_adherence`) now exist in the sandbox; the dataset revision should expose a **closed vocabulary of field presence codes** so offline and Modal scorers agree.

### 3.3 ML head collapse (data-side)

mailroom-ml run-3: contract macro-F1 **0.0395**, correspondence **0.0845** (#112). Corpus-side contributors already diagnosed:

- Enron enrichment without subclass balance amplifies **97.9% email** (#114).
- CUAD full pool pinned but unwired (#113); mixture_caps alphabetical starvation (#115).
- v9.1 should **not** pretend to fix training code, but **must** improve eval partition fairness (test floor) and publish **subclass support tables / enrichment-safe draws** so mailroom-ml Tier-1 cannot silently deepen majority collapse.

### 3.4 Provider seam unblocks #30

`intent_backfill.py` / coverage matrix already name `VLLM_BASE_URL` + Modal as the clause-pass provider. With sandbox Modal live, the EX-10 annotation path is no longer theoretically blocked — only credential/routing wiring remains.

## 5. Technical approach (HF revision shape)

### 5.1 Versioning & identity

- New Hub revision on `Lucius-Morningstar/mailroom-dataset` (same repo; successor tip).
- Card: bump `dataset_version` → `v1.1`; lineage note "v9.1 quality revision of v9 / tip `46a4d3c2…`".
- **Zero identity drift** for rows whose content is unchanged (`document_id`, `content_sha256` stable).
- Rows whose GT changes (91 EX-10 clause fills; intent reviews; presence maps) keep `document_id` and bump `annotation_*` / `source_revision` provenance.

### 5.2 Configs

| Config | Change |
|---|---|
| `default` | Hardened blind metadata; optional `token_estimate` **only if** proven non-leaky (prefer keep estimates in GT/sidecar) |
| `ground_truth` | +`gt_presence` / eligibility; filled EX-10 clauses; reviewed intents; window hints |
| `bundles` | Expand multi-doc families over real anchors; keep `synthetic_constructed` flags |
| `streams` | Refresh to include new bundle matters + format-failure distractors |
| `fixtures` | Populate challenge/calibration/failure-stage with real adversarial + unreadable samples |

### 5.3 Publish path (no ad-hoc uploads)

1. Stage via `dataset_export.stage_parquet` + JSONL sidecars (`safe_jsonl_line`).
2. Upload via `mailroom_eda.hf_interface`.
3. Byte-verify with `scripts/publish/verify_hf.py`.
4. Re-run `run_all.py` full P0–P6; commit updated `SUMMARY_REPORT.*` + audits (not regenerated interactive HTML — HUB-008).
5. Propagate monorepo-ward via `scripts/sync_packages.py` (one-way).

## 6. Phased implementation checklist

### Phase A — Provider & annotation close-out (P0)

- [ ] **A1.** Wire clause-pass CLI to Modal OpenAI-compatible endpoint (`VLLM_BASE_URL` / `VLLM_API_KEY`) using the same provider seam as `backfill_intent.py`.
- [ ] **A2.** Run constrained CUAD clause pass (temp 0.1, JSON) over exactly the **91** EX-10 filenames catalogued in `docs/reports/audits/cuad_ex10_annotation_review.md`.
- [ ] **A3.** Human gate sample (≥10% stratified by subclass); record `annotation_model`, `annotation_prompt_version`, `annotation_confidence`, `annotation_status`.
- [ ] **A4.** Flip coverage-matrix absence rule; remove dated exception; update tests/pins.
- [ ] **A5.** Adjudicate **25** `flagged_review` intents (manual or second-pass Modal); keep provenance columns honest.

**Exit:** `cuad_clause_labels` eligible coverage 600/600; intent_status flagged_review ≤ policy threshold.

### Phase B — LLM-safe formatting & scorer contract (P0)

- [ ] **B1.** Extend `HARD_LEAK_KEYS` / blind strip to remove `clause_count`, `maud_label_count`, and any label-derived aggregates from `default.metadata` (preserve on GT if needed for analytics).
- [ ] **B2.** Add row-level `gt_presence` (or expand `gt_fields`) with closed codes: `populated` \| `schema_documented_absence` \| `not_applicable` \| `pending_annotation` — mirroring audit absence rules so Modal scorers skip empty non-insurance fields correctly (#21/#32).
- [ ] **B3.** Normalize `prompt` stems per specialist to field-level empty/null rules (ingest-time mirror of SAND-026), still label-free.
- [ ] **B4.** Publish `chars_per_token: 4.0` + `token_estimate` on GT; add `context_windows_required` heuristic bands matching Modal (`<=4k`, `<=16k`, `<=32k`, `>32k`).
- [ ] **B5.** Add publish-time leak guard test + Hub tip byte-verify of blind columns == `{filename,doc_text,prompt,metadata[,split]}`.

**Exit:** Blind tip has zero label/aggregate leaks; sandbox empty-GT scoring can key off presence codes without hard-coding class lists.

### Phase C — Eval partition & imbalance (P1)

- [ ] **C1.** Implement **per-stratum test floor**: for every stratum with ≥1 row, ensure ≥1 test row when total ≥10; for totals <10, allow train-only but flag `eval_stratum_risk` (do **not** break md5 split for existing rows — prefer **additive** reserved eval draws or a `eval_fold` sidecar rather than reshuffling the published 90/10).
- [ ] **C2.** Targeted minority expansion (evaluation value): merger election / mixed strata; contract `Non_Compete_Non_Solicit`; correspondence `attorney_demand` — prefer licensed public sources already in the family.
- [ ] **C3.** Export subclass support tables consumed by mailroom-ml enrichment (caps, target shares) so Tier-1 Enron draws cannot amplify email majority (#114).

**Exit:** Zero-test strata among totals ≥10 reduced to 0; support tables published as Hub sidecar.

### Phase D — Scenario / fixture graduation (P1–P2)

- [ ] **D1.** Populate `fixtures` challenge + arbiter scenarios with real ambiguous / adversarial docs (exit scaffold-only state called out in expansion priorities).
- [ ] **D2.** Expand `bundles` multi-document families using family-sampled real anchors (contract+amendment+exhibit; correspondence threads where subject+custodian allows).
- [ ] **D3.** Add format-diversity ingestion failures (corrupt encodings, OCR-garbage scans) flagged for §58 — sequenced after D1.
- [ ] **D4.** Mark covered scenario axes on fixture/bundle rows (`challenge`, `multi_document`, `ingestion`) so coverage matrix is no longer all-zero on those configs.

**Exit:** Expansion-priority HIGH items have non-zero coverage on fixtures/bundles configs.

### Phase E — Publish, verify, propagate (P0)

- [ ] **E1.** Deterministic rebuild (`RANDOM_STATE=42`); sorted JSONL byte-stable for unchanged rows.
- [ ] **E2.** Upload revision; `verify_hf.py` parity; update dataset card + AGENTS.md HF facts.
- [ ] **E3.** Full `run_all.py` P0–P6; commit summary + static audits (leave interactive HTML untouched).
- [ ] **E4.** Sync package → Digital-Mailroom; notify mailroom-ml / sandbox / pipeline to pin new revision.
- [ ] **E5.** Re-run Modal correspondence draw on fingerprint protocol with presence-aware scoring; target diagnostic ≥0.25 before claiming pipeline win.

## 9. Acceptance criteria (revision DoD)

1. Hub tip advances past `46a4d3c2…` with verified parquet/JSONL parity.
2. EX-10 `cuad_clause_labels` no longer a dated exception (eligible coverage 100% or explicitly `pending_annotation` with live credential ticket — not silent `{}`).
3. Blind config passes expanded leak guard (no labels, no label-derived aggregates).
4. Every GT field used by sandbox scorers has a presence code; empty non-applicable fields are not scorable as misses.
5. Token/context bands published; merger rows flagged `>32k`.
6. Among strata with total ≥10, zero-test count = 0 **or** documented `eval_fold` covering them.
7. Fixtures/bundles show non-zero `challenge` and `multi_document` coverage.
8. EDA summary + coverage matrix regenerated and committed; AGENTS.md HF facts updated.
9. Downstream pins recorded (sandbox + mailroom-ml + pipeline).
